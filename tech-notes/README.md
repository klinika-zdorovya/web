# tech-notes

Папка для обсуждения и фиксации технических решений по проекту (хостинг,
домен, инфраструктура, деплой, сторонние сервисы) и хранения связанных
документов — то, что не является ни контентом сайта (`content/`), ни
пользовательской документацией проекта (`documentation/`).

## Структура

- `DECISIONS.md` — журнал технических вопросов и решений, по одной записи на
  тему/дату. Формат — как в корневом `DIARY.md`: что обсуждали, что решили,
  почему, что дальше.
- `docs/` — исходные документы: исследования, экспорты переписки/ответов от
  внешних инструментов (например, ответы Perplexity), инструкции от
  хостинг-провайдера и т.п., а также готовые клиентские отчёты. Всё по одной
  теме/инциденту лежит в подпапке `docs/YYYY-MM-DD/` (дата — когда произошёл
  инцидент/выполнена работа), файлы внутри — без даты в имени, например
  `docs/2026-08-11/otchet-ssl.pdf`, `docs/2026-08-11/ssl-sertifikat-issledovanie.md`.
- `templates/report/` — единый шаблон/дизайн-система для клиентских отчётов
  (PDF + HTML), с инструментами сборки. **Все отчёты заказчику оформляются
  через этот шаблон** — см. `templates/report/README.md`.

## Правила

- **Никогда не класть сюда секреты**: приватные ключи (`privkey.pem`),
  пароли, токены, содержимое `.env`. Если документ из внешнего источника
  такое содержит — вычищать перед сохранением.
- Обновлять `DECISIONS.md`, когда вопрос решён или статус изменился —
  не только когда завели тему.
- Эта папка коммитится в git (в отличие от `legacy-docs/`, который в
  `.gitignore`) — исходи из того, что содержимое может стать публичным при
  публикации репозитория.
