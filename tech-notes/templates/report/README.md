# Шаблон клиентского отчёта

Единый формат для отчётов, которые предъявляются заказчику (клинике) по
выполненным техническим работам. Первый пример по этому шаблону —
`tech-notes/docs/2026-08-11/otchet-ssl.{html,pdf}` (инцидент с
SSL-сертификатом).

## Из чего состоит

- `style.css` — дизайн-система (цвета, типографика, компоненты: карточка
  сводки, таймлайн хода работ, таблица фактов, рамка браузера под скриншот,
  список рекомендаций, футер с подписью). Правится один раз — правки
  применяются ко всем будущим отчётам при пересборке.
- `fonts-inline.css` — шрифты, инлайновые (base64), с поддержкой кириллицы:
  **PT Serif** (заголовки, подпись в футере) + **PT Sans** (текст) — пара от
  ParaType, изначально сделана для кириллицы и официальных документов;
  **IBM Plex Mono** (числа, версии, id, технические значения). Скачаны один
  раз, повторно скачивать не нужно.
- `template.html` — скелет отчёта с плейсхолдерами `ЗАПОЛНИ:` и пояснениями
  в комментариях, что можно убирать/добавлять.
- `build.py` — собирает шрифты + стили + заполненный контент в один
  самодостаточный HTML-файл.
- `render_pdf.mjs` — рендерит собранный HTML в PDF через локальный Chrome
  (Playwright, `channel: 'chrome'` — использует уже установленный на машине
  Google Chrome, отдельно скачивать браузер не нужно).

## Как сделать новый отчёт

Каждый отчёт лежит в своей папке по дате инцидента/работы:
`tech-notes/docs/YYYY-MM-DD/`. Имена файлов внутри — без даты (она уже в
имени папки) и без слова «заказчику»: `otchet-<тема>.pdf`,
`otchet-<тема>.html`, `otchet-<тема>-content.html` и т.п.

1. Создать папку `tech-notes/docs/YYYY-MM-DD/` (дата — когда произошёл
   инцидент/выполнена работа, не обязательно дата написания отчёта).
2. Скопировать `template.html` в `tech-notes/docs/YYYY-MM-DD/otchet-<тема>-content.html`
   и заполнить все `ЗАПОЛНИ:`.
3. Если есть скриншот-подтверждение — получить base64:
   ```bash
   sips -Z 1000 screenshot.png --out screenshot_small.png
   sips -s format jpeg -s formatOptions 78 screenshot_small.png --out screenshot.jpg
   base64 -i screenshot.jpg -o screenshot.b64
   ```
   Вставить содержимое `screenshot.b64` вместо `__HERO_IMAGE_B64__` в файле
   контента (или скриптом `sed`/Python — см. пример в `build.py`, логика та
   же: замена плейсхолдера). Сам файл скриншота, если нужен отдельно, тоже
   кладётся в `tech-notes/docs/YYYY-MM-DD/`.
4. Собрать самодостаточный HTML:
   ```bash
   python3 build.py content.html tech-notes/docs/YYYY-MM-DD/otchet-<тема>.html
   ```
5. Установить зависимости (один раз для машины/проекта) и собрать PDF:
   ```bash
   npm install            # в этой папке, один раз
   node render_pdf.mjs tech-notes/docs/YYYY-MM-DD/otchet-<тема>.html \
                        tech-notes/docs/YYYY-MM-DD/otchet-<тема>.pdf
   ```
6. Проверить PDF визуально (количество страниц, разрывы) — при необходимости
   подправить контент/`style.css` в блоке `@media print` и пересобрать.
7. При необходимости — опубликовать HTML-версию как Artifact (для показа в
   браузере со ссылкой), PDF — как файл для отправки/печати.

## Принципы оформления (не менять без причины)

- Один цвет — статусный (`--good`/`--good-soft`, зелёный «Решено»), другой —
  декоративный акцент (`--accent`/`--accent-strong`, тёплый янтарный,
  перекликается с цветами на самом сайте клиники). Не путать одно с другим:
  для нового статуса (например, «в процессе») — заводить свой токен, не
  красить акцентом.
- Таймлайн (`.timeline`) — только когда порядок шагов реально важен
  (диагностика → причина → исправление → проверка). Если это не так —
  обычный список без таймлайна.
- Технические значения (номера заказов, версии, даты, домены, статусы
  протоколов) — моноширинным (`IBM Plex Mono`, класс `.fact-value` /
  `.meta-value.mono`), не основным шрифтом.
- Разделы нумеруются (`01`, `02`, ...), только если это реально
  последовательность действий/логики отчёта — не декоративная нумерация.
- Обе цветовые темы (светлая/тёмная) поддерживаются автоматически через CSS
  custom properties — при правке `style.css` новые цвета добавлять и в
  `:root`, и в `@media (prefers-color-scheme: dark)`, и в
  `:root[data-theme="dark"]` (см. существующие токены как образец).
